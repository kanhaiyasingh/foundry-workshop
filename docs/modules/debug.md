them **before** starting so participants don't hit the 401/403/Forbidden errors
above. There are two identities to think about:

- **You (user principal)** — the signed-in `az login` identity that runs the
  notebooks.
- **Foundry project managed identity (MI)** — the identity Foundry uses to reach
  out to Search / Storage / Cosmos on your behalf (grounding, agents, eval/RAI).

## Conventions while debugging these labs

- **Auth:** `AzureCliCredential` (`az login`) is faster and more reliable than `DefaultAzureCredential` in this environment.
- **Embeddings:** use the **account** `/openai/v1/` endpoint; **chat / responses / agents** use the **project** endpoint.
- **403 / 401 / Forbidden:** check the backing data store first — Search auth mode (`apiKeyOnly` vs `aadOrApiKey`), RBAC roles, and connection **type** — before suspecting code.
- **Agent creation (`create_version`) hitting Cosmos:** the preview versioned-agent API stores agent definitions in the project's BYO Cosmos. A `403 "blocked by your Cosmos DB account firewall"` on `create_version`/`list_versions` usually means Cosmos `publicNetworkAccess=Disabled` — and the blocked caller is **Foundry's service**, not your IP, so enable public access (or a private endpoint).
- **`.env` changes not taking effect:** ensure the cell uses `load_dotenv(override=True)`; otherwise VS Code's injected env wins.
- These are **generated** notebooks — local edits are overwritten if `scripts/gen_<id>.py` is re-run. Most fixes here are environment/config, not code bugs.
